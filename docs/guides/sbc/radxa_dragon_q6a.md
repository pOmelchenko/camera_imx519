# IMX519 на Q6A CAM3

Проверено 2026-10-11: Radxa Dragon Q6A, CAM3/J7, имеющийся модуль
Arducam IMX519 с объективом 80°, Ubuntu 24.04.5 LTS, ядро `7.0.11-7-qcom`.
Ревизия PCB и поконтактная схема фактически установленного шлейфа не
зафиксированы. Подключение владельца работает; перенос на другую ревизию
требует сверки [распиновки](../../reference/pinout.md).

## Установленная конфигурация

[Код, закреплённые источники и сборка](../../../target/sbc/radxa_dragon_q6a/README.md).
Установлены модули IMX519/AK7375 из этой платформы. Активный BLS entry:
`/boot/efi/loader/entries/RadxaOS-7.0.11-7-qcom.conf`.
Его строка камер:

```text
devicetree-overlay /RadxaOS/7.0.11-7-qcom/dtbo/ar0234-cam2.dtbo /RadxaOS/7.0.11-7-qcom/dtbo/imx519-cam3.dtbo
```

IMX519 CAM1/2 остаются `imx519-cam1.dtbo.disabled` и
`imx519-cam2.dtbo.disabled`; в BLS entry их нет. Прежний AR0234 CAM2 сохранён.
Это конкретное проверенное сочетание, а не требование иметь AR0234.
В `/etc/modules-load.d/imx519-cam3.conf`:

```text
i2c_qcom_cci
qcom_camss
ak7375
imx519
```

CAM3 использует GPIO78, CCI1/I2C1, CSIPHY3, сенсор `0x1a`, привод `0x0c`.
Оверлей задаёт I2C 400 кГц и паузу питания 100 мс. На унаследованных
1 МГц запись `0x0100` завершалась timeout; на 400 кГц поток запустился.
Патч драйвера сохраняет проверку ID `0x0519`, адаптирует metadata pad
и исправляет runtime PM при ошибке probe. Регистры режимов не изменены.

Для первого включения сохранить исходный boot entry и иметь доступный
резервный вариант загрузки. На проверенной плате создан entry
`Q6A-before-imx519-cam3.conf` с прежним AR0234 CAM2. В
`/home/radxa/camera-imx519-20261011/boot-backup-cam3` сохранены исходные
файлы, а `restore-imx519-cam3.py` восстанавливает конфигурацию до включения
IMX519; после его запуска нужна перезагрузка. Общая установка ОС и boot
firmware — в [репозитории платы](https://github.com/pOmelchenko/radxa_dragon_q6a).

## Проверка и просмотр

После загрузки:

```sh
cam -l
media-ctl -d /dev/media0 -p
sudo dmesg | grep -Ei 'imx519|ak7375|cci.*(error|timeout)'
```

Ожидаемый ID камеры:
`/base/soc@0/cci@ac4b000/i2c-bus@1/imx519@1a`.
Сенсор регистрируется автоматически; ручная привязка после загрузки не нужна.
На проверенной плате узлы — `/dev/v4l-subdev28` (IMX519) и
`/dev/v4l-subdev29` (AK7375). Номера могут меняться.

Из каталога `target/sbc/radxa_dragon_q6a` в терминале рабочего стола:

```sh
sh tools/preview.sh --compare
```

Ограниченный прогон со снимком:

```sh
capture_dir=$(mktemp -d "$HOME/imx519-demo.XXXXXX")
sh tools/preview.sh --compare --frames=600 --snapshot="$capture_dir/comparison.ppm"
```

Перед вторым просмотром закрыть первый. В текущей сессии проверенная демка
оставлена открытой через `imx519-preview.service`; из терминала рабочего стола
её можно остановить: `systemctl --user stop imx519-preview.service`.
Это временный сервис, автозапуск после следующей загрузки не настроен.
[Клавиши и параметры демки](../../../target/sbc/radxa_dragon_q6a/demo/README.md).

## Результат и границы проверки

Демка получила 600 кадров за 20,3709 с, частота по timestamps — 29,9002 кадр/с,
пропуски и ошибки — 0. Вход simple/software ISP — 2328×1748 RGGB RAW10
CSI2P, stride 2912; выход — 1920×1080 XBGR8888/sRGB, stride 7680.
Снимок 3840×1080 содержит исходник слева и обработку справа.
Сохранённая сцена видна, но изображение тёмное и не сфокусировано.
После этого оставленный просмотр дошёл до 6696 отображённых кадров,
ошибок захвата — 0; демка отбросила 100 устаревших кадров при отставании
рендера. Это отдельный счётчик от ошибок захвата, а не гарантия отображения
каждого кадра в длительном прогоне.

Используется `uncalibrated.yaml`; sensor helper и отдельного tuning IMX519
нет. Цвет, экспозиция и фокус требуют настройки. AK7375 зарегистрирован
с `focus_absolute` 0–4095, но движение объектива и AF не проверялись.
Демка не содержит алгоритма AF. Cold boot, полный режим 4656×3496,
CAM1/2 и одновременный захват двух камер не проверены.
