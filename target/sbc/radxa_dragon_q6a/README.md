# Arducam IMX519 на Radxa Dragon Q6A, CAM3

Комплект для повторения настройки: исходники драйверов, overlay, скрипты и
журнал проверок. Копия на плате: `/home/radxa/camera-imx519`.
SSH-адрес платы задаётся через `IMX519_SSH_TARGET` или аргумент скрипта.
Исходный комплект проверен 2026-09-09;
контрастный автофокус проверен 2026-09-25 (Москва).

## Текущее состояние

**Базовая настройка завершена: RAW и цветной захват работают.** Отдельная сборка
libcamera содержит корректный IMX519 helper и базовый профиль: автоматическое
усиление работает, предупреждения исчезли. Ручное управление линзой проверено
на изображениях. Отдельная сборка `imx519.af1` поддерживает однократный и
непрерывный **контрастный** AF. Фазовый AF и цветовая калибровка не завершены;
подробности и ограничения в [исследовании](research/autofocus.md).

## Команды на уже настроенной плате

```sh
cd ~/camera-imx519
bash snapshot.sh                    # снимок 1080p с фокусом, после 90 кадров AE/AWB
bash snapshot-af.sh auto            # снимок после однократного CDAF
bash snapshot-af.sh continuous      # снимок после непрерывного CDAF
bash check.sh                       # устройства, топология, libcamera
bash capture.sh raw                 # 3 кадра RAW 1920×1080
bash capture.sh rgb                 # 3 цветных кадра 1920×1080, PPM
bash collect-diagnostics.sh          # сохранить диагностический снимок
```

Захват выполняется от пользователя `radxa` без sudo. Каждый запуск создаёт
отдельную папку в `artifacts/`: точная команда, время UTC, ядро, лог, код
завершения и кадры. Таймаут по умолчанию 30 секунд, старые кадры не заменяются.
Номера `/dev/video*` не зашиты в скрипт: используется проверенный ID камеры
`/base/soc@0/cci@ac4b000/i2c-bus@1/camera@1a`.

```sh
# Другой размер, число кадров и каталог результатов:
IMX519_WIDTH=640 IMX519_HEIGHT=480 bash capture.sh rgb 30 ~/camera-tests
# Для более долгого теста увеличить таймаут:
IMX519_TIMEOUT=60 bash capture.sh raw 300
# Полный журнал ядра: sudo только для его чтения, файлы остаются у radxa:
sudo -v
bash collect-diagnostics.sh
```

libcamera может скорректировать запрошенный размер/формат; фактические
параметры записываются в `capture.log`. В скрипте доступны также
`IMX519_CAMERA` и `--help`. Скрипт возвращает ошибку при таймауте,
ошибке cam/записи лога или неожиданном числе файлов.

`cam.sh`, `capture.sh` и диагностика автоматически выбирают отдельную
libcamera из `runtime/current`, если она установлена. Для сравнения со
штатной сборкой: `IMX519_LIBCAMERA=system bash capture.sh rgb`.
Для строгого требования отдельной сборки: `IMX519_LIBCAMERA=private`.
Простой вызов `/usr/bin/cam` продолжает использовать системный пакет.

Сборка/развёртывание отдельной libcamera с рабочего компьютера:

```sh
export IMX519_SSH_TARGET='radxa@<board-address>'
bash hardware/camera/imx519/q6a/libcamera/build-runtime.sh   # Docker, Ubuntu 24.04 arm64
bash hardware/camera/imx519/q6a/libcamera/deploy-runtime.sh # SHA-256 и cam -l
```

Исходники закреплены на commit `de1e9bc095e23085e77533357d2582176de0a582`,
сначала применяются Debian patches, затем `libcamera/imx519.patch` и
`libcamera/autofocus-simple.patch`.
Все 8 тестов IPA прошли, включая проверку IMX519 gain/black level.
Установка в домашний каталог не требует sudo; старые runtime-каталоги
сохраняются. Для возврата к системной сборке достаточно
`IMX519_LIBCAMERA=system`. Профиль — базовый, не измерительная калибровка цвета.

Ручной фокус нужно удерживать на время захвата: закрытие subdev паркует линзу.

```sh
python3 focus.py "$(cat focus-position.txt)" -- bash capture.sh rgb 60
bash focus-sweep.sh             # грубый проход, 9 положений; последние PPM и логи
bash focus-sweep.sh 2496 2560 2624 2688  # уточнение на неподвижной сцене
python3 score-focus.py artifacts/focus-20260908T230816Z.wfp98H/focus-*.ppm
```

Код для snapshot.sh/preview.sh хранится в focus-position.txt; его можно
переопределить аргументом или IMX519_FOCUS. Это не универсальная дистанция
фокусировки. После перемещения камеры/предмета требуется новый подбор.
Сравнивать нужно кадры одного прохода и выбранную область одного предмета,
расположенного на нужной глубине. После перемещения предметов на 20 см
выполнены новый грубый проход и уточнение на 1080p: код 2496 снова дал
лучший результат по выбранной области с деталями. Он записан по умолчанию.
Соседний 2432 дал близкую оценку; это практический выбор, не метрологическая
калибровка расстояния или гарантия резкости предметов на другой глубине.

В терминале **графического рабочего стола Radxa** для просмотра:

```sh
bash preview.sh
```

В обычном SSH-сеансе у qcam нет дисплея; там используйте snapshot.sh.
Само окно qcam на дисплее агентом не проверялось; бинарник собирается и
выдаёт --help через QT_QPA_PLATFORM=offscreen. Qt-библиотеки
устанавливаются вместе с qcam в пакете libcamera-tools.

## Повторная установка с исходников

На рабочем компьютере из каталога этого проекта:

```sh
export IMX519_SSH_TARGET='radxa@<board-address>'
bash hardware/camera/imx519/q6a/sync-to-radxa.sh
ssh "$IMX519_SSH_TARGET"
```

Скрипт передаёт исходники, документацию и выбранные доказательства из docs.
Он не переносит build/artifacts и бинарные модули, не удаляет результаты
на плате и не меняет загрузку.
Удалённый rsync не нужен. На **плате с указанным выше ядром**:

```sh
sudo apt-get update
sudo apt-get install -y build-essential linux-headers-$(uname -r) device-tree-compiler dkms
cd ~/camera-imx519
bash build.sh
sudo bash install.sh
sudo reboot
```

После загрузки выполните `check.sh`, `capture.sh raw`, `capture.sh rgb` и
сохраните снимок `collect-diagnostics.sh`. Сборка сверяет хеши исходников,
компилирует модули, проверяет vermagic и наложение overlay на штатный DTB.
Само ядро целиком не пересобирается.

Установщик проверяет модель, ядро и конфликты CAM3, устанавливает
libcamera/V4L2-инструменты и DKMS-модули. Перед включением overlay сохраняет
конфигурацию в `/var/backups/imx519-cam3.*`. Использует каталоги и функции
установленного rsetup для EFI и присутствующей конфигурации U-Boot.
Автоматической перезагрузки нет. Повторно запускать установщик только ради
захвата кадров не требуется.

Системные изменения требуют пароля sudo, которого нет в неинтерактивном
SSH-сеансе агента. Пароль вводится в терминале платы.

## Подключение и overlay

CAM3 подтверждён пользователем. Привязка: CCI1/I2C1, сенсор `0x1a`, линза
`0x0c`, CSIPHY3, GPIO78 включения модуля; clock 24 MHz, link frequency
408 MHz из используемого драйвера. Пакет резервирует 256 MiB CMA.
Штатные overlay IMX219/IMX708 для CAM3 должны оставаться выключенными.

Номера I2C-шины, media и subdev могут меняться. В проверенном запуске:
`20-001a`, `20-000c`, `/dev/media0`, `/dev/v4l-subdev27`, `/dev/v4l-subdev28`.
`/dev/video0` и `/dev/video1` принадлежат Iris codec.

## Отключение и обновления

В `sudo rsetup` → Overlays → Manage overlays снимите отметку
`Enable Arducam IMX519 on CAM3 (experimental)`, сохраните и перезагрузитесь.
Это отключает камеру; исходники и DKMS-пакет остаются для повторного включения.
Процедура отключения описана по rsetup, на работающей камере не проверялась.

При проблеме загрузки можно выбрать оставшееся ядро `6.18.2-3-qcom` в EFI-меню;
его EFI overlay установщик не меняет. Этот способ восстановления не проверялся.
Старая конфигурация U-Boot может ссылаться на общий `/boot/dtbo`, поэтому
старое ядро в U-Boot не следует считать гарантированным откатом overlay.

После обновления ядра DKMS попробует пересобрать модули. Новый ABI и перенос
пользовательского overlay в EFI-каталог нового ядра нужно проверить отдельно.
Установщик намеренно ограничен уже проверенным `7.0.11-6-qcom`.

## Проверено и границы настройки

- Драйверы/overlay установлены, прошли перезагрузку и распознавание камеры.
- Собрана и аппаратно проверена отдельная libcamera с IMX519 helper.
- После повторной перезагрузки проверены отдельная libcamera, профиль v2,
  снимок с фокусом 2496 и RAW-захват. Параметр AC autosuspend radxa сохранился
  как `nothing`; повторная установка или ручное включение камеры не потребовались.
- Исправлены автоусиление и предупреждения; профиль экспозиции v2 уменьшает
  пересветы контрольной сцены. Это не измерительная цветовая калибровка.
- Проверено ручное движение линзы и изменение резкости; есть команды
  подбора, снимка и предпросмотра.
- Успешны 9000 RGB кадров / 300 секунд, повторные снимки и RAW-захват;
  после изменения только YAML — ещё 1800 кадров / 60 секунд без ошибок.
- Причина обрыва SSH доказана полным журналом: системный сон s2idle.
  Пользователь отключил AC autosuspend GDM/radxa через disable-autosuspend.sh.
  Откат: `sudo bash /var/backups/imx519-autosuspend.9uYvqG2y/restore.sh`.

На момент этого опыта 2026-09-09 непрерывный автофокус не был включён.
Контрастный AF добавлен 2026-09-25; фазовый путь остаётся открытым.
Максимальное разрешение, другие частоты кадров,
цветовая/оптическая калибровка и поведение на новом ядре остаются отдельными проверками.
Системные libcamera-пакеты и параметры загрузки в этом продолжении не менялись.

Для повторного теста без записи всех кадров:

```sh
python3 focus.py "$(cat focus-position.txt)" -- bash stability.sh rgb 9000
```

Профиль `libcamera/tuning/simple/imx519.yaml` используется первым.
В runtime также сохранён первоначальный базовый профиль из сборки.
Чтобы сравнить с ним: `IMX519_TUNING_DIR="$PWD/runtime/current/share/libcamera/ipa" bash snapshot.sh`.
Целевая MSV яркость изменена с 2.5 на 2.0; gamma 2.2, AWB speed 0.2.
Путь фактически выбранного YAML записывается в capture.log.
