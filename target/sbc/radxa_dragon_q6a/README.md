# Arducam IMX519 на Radxa Dragon Q6A, CAM3

Комплект для повторения настройки: исходники драйверов, overlay, скрипты и
журнал проверок. Копия на плате: `/home/radxa/camera-imx519`.
SSH-адрес платы задаётся через `IMX519_SSH_TARGET` или аргумент скрипта.
Исходный комплект проверен 2026-09-09; контрастный и экспериментальный
фазовый автофокус проверены 2026-09-25 (Москва).

## Текущее состояние

**Базовая настройка завершена: RAW и цветной захват работают.** Отдельная сборка
libcamera содержит корректный IMX519 helper и базовый профиль: автоматическое
усиление работает, предупреждения исчезли. Ручное управление линзой проверено
на изображениях. Отдельная сборка `imx519.pdaf5` выполнила однократную и
непрерывную фазовую наводку внутри libcamera на одной освещённой неподвижной
сцене. При нестабильной фазе она переходит на контрастный AF. Длительная
проверка PDAF и цветовая калибровка не завершены; подробности в
[исследовании](research/autofocus.md).

## Команды на уже настроенной плате

```sh
cd ~/camera-imx519
bash snapshot.sh                    # снимок 1080p с фокусом, после 90 кадров AE/AWB
bash snapshot-af.sh auto            # снимок после однократного AF: PDAF или резервный CDAF
bash snapshot-af.sh continuous      # снимок после Continuous AF; перенаводка в движении не проверена
python3 snapshot-pdaf.py            # однократный фазовый фокус и снимок; нужен экспериментальный CAMSS
bash check.sh                       # устройства, топология, libcamera
bash capture.sh raw                 # 3 кадра RAW 1920×1080
bash capture.sh rgb                 # 3 цветных кадра 1920×1080, PPM
bash collect-diagnostics.sh          # сохранить диагностический снимок
```

Захват выполняется от пользователя `radxa` без sudo. Каждый запуск создаёт
отдельную папку в `artifacts/`: точная команда, время UTC, ядро, лог, код
завершения и кадры. Таймаут по умолчанию 30 секунд, старые кадры не заменяются.
Номера `/dev/video*` не зашиты в скрипт: используется проверенный ID камеры
`/base/soc@0/cci@ac4b000/i2c-bus@1/camera@1a`.

```sh
# Другой размер, число кадров и каталог результатов:
IMX519_WIDTH=640 IMX519_HEIGHT=480 bash capture.sh rgb 30 ~/camera-tests
# Для более долгого теста увеличить таймаут:
IMX519_TIMEOUT=60 bash capture.sh raw 300
# Полный журнал ядра: sudo только для его чтения, файлы остаются у radxa:
sudo -v
bash collect-diagnostics.sh
```

libcamera может скорректировать запрошенный размер/формат; фактические
параметры записываются в `capture.log`. В скрипте доступны также
`IMX519_CAMERA` и `--help`. Скрипт возвращает ошибку при таймауте,
ошибке cam/записи лога или неожиданном числе файлов.

`cam.sh`, `capture.sh` и диагностика автоматически выбирают отдельную
libcamera из `runtime/current`, если она установлена. Для сравнения со
штатной сборкой: `IMX519_LIBCAMERA=system bash capture.sh rgb`.
Для строгого требования отдельной сборки: `IMX519_LIBCAMERA=private`.
Простой вызов `/usr/bin/cam` продолжает использовать системный пакет.
`snapshot-pdaf.py` при недоступном или недостоверном фазовом потоке запускает
уже проверенный `snapshot-af.sh auto` и сохраняет причину перехода в `result.json`.
Это отдельный однократный сценарий. Частная сборка libcamera теперь принимает
фазовые буферы `/dev/video4` при цветном захвате и переключается на CDAF,
если фазовые образцы пропали или нестабильны.

Исходники миры и PDF A4 для печати сохранены в
[общем каталоге мишеней](test-charts/README.md). Для снимка всей миры на
расстоянии около 22 см используйте формат 4:3.
После перезагрузки со штатным CAMSS выберите `runtime/preview` для
контрастного AF и остановите веб-предпросмотр перед захватом:

```sh
cd ~/camera-imx519
systemctl --user stop imx519-web-preview.service
IMX519_RUNTIME="$PWD/runtime/preview" IMX519_WIDTH=1920 IMX519_HEIGHT=1440 bash snapshot-af.sh auto
```

`snapshot-af.sh` по умолчанию сохраняет размер 1920×1080. Для фазового AF
используйте `runtime/current` только после загрузки экспериментального CAMSS.

Сборка/развёртывание отдельной libcamera с рабочего компьютера:

```sh
export IMX519_SSH_TARGET='radxa@<board-address>'
bash target/sbc/radxa_dragon_q6a/libcamera/build-runtime.sh   # Docker, Ubuntu 24.04 arm64
bash target/sbc/radxa_dragon_q6a/libcamera/deploy-runtime.sh # SHA-256 и cam -l
```

Исходники закреплены на commit `de1e9bc095e23085e77533357d2582176de0a582`,
сначала применяются Debian patches, затем `libcamera/imx519.patch`,
`libcamera/autofocus-simple.patch`, `libcamera/color-native-size.patch` и
`libcamera/pdaf-simple.patch`.
Все 8 тестов IPA прошли, включая проверку IMX519 gain/black level.
Установка в домашний каталог не требует sudo; старые runtime-каталоги
сохраняются. Для возврата к системной сборке достаточно
`IMX519_LIBCAMERA=system`. Профиль — базовый, не измерительная калибровка цвета.

Для цветного захвата через новую libcamera задавайте ручной код через
`LensPosition`: при запуске камеры она может сбросить значение, выставленное
заранее через `focus.py`. `snapshot.sh` и `focus-sweep.sh` создают нужный
сценарий автоматически и выбирают `runtime/preview`, если он есть. Явный
`IMX519_RUNTIME` имеет приоритет.

```sh
bash snapshot.sh 2305          # ручной фокус для текущей миры, 1080p
IMX519_WIDTH=1920 IMX519_HEIGHT=1440 bash snapshot.sh 2305  # весь лист в 4:3
bash focus-sweep.sh             # грубый проход, 9 положений; последние PPM и логи
IMX519_WIDTH=1920 IMX519_HEIGHT=1440 bash focus-sweep.sh 2240 2305 2368  # уточнение
python3 score-focus.py artifacts/focus-20260908T230816Z.wfp98H/focus-*.ppm
```

Код по умолчанию для `snapshot.sh` и `web-preview.py` хранится в
`focus-position.txt`; его можно переопределить аргументом или `IMX519_FOCUS`
для снимка. Это не универсальная дистанция
фокусировки. После перемещения камеры/предмета требуется новый подбор.
Сравнивать нужно кадры одного прохода и выбранную область одного предмета,
расположенного на нужной глубине. На прежней сцене около 20 см в 2026-09-09
был выбран код 2496 (соседний 2432 дал близкую оценку). Для нынешней миры
около 22 см AF и ручное уточнение выбрали код 2305; он записан по умолчанию.
Это практический выбор, не метрологическая калибровка расстояния или
гарантия резкости предметов на другой глубине. На сохранённом кадре миры
мелкие детали остаются мягкими, яркость по полю неравномерна; качество
изображения ещё не квалифицировано.

В терминале **графического рабочего стола Radxa** для просмотра:

```sh
bash preview.sh
```

В обычном SSH-сеансе у qcam нет дисплея; там используйте snapshot.sh.
`qcam` не принимает сценарий `LensPosition` через командную строку, поэтому
`preview.sh` не принимает код фокуса. Для просмотра с фиксированным кодом
используйте `web-preview.py`.
Само окно qcam на дисплее агентом не проверялось; бинарник собирается и
выдаёт --help через QT_QPA_PLATFORM=offscreen. Qt-библиотеки
устанавливаются вместе с qcam в пакете libcamera-tools.

Для установки миры без экрана платы есть предпросмотр в браузере. Он берёт
цветной кадр 1920×1440 после 90 кадров прогрева экспозиции через тот же
`cam.sh`, обновляет его примерно раз в несколько секунд и держит фиксированный
код линзы из `focus-position.txt` через `LensPosition` libcamera. Формат 4:3
позволяет увидеть весь лист A4 при расстоянии около 22 см. `snapshot.sh`
по умолчанию снимает в 1920×1080 и обрежет верх и низ такой композиции;
для полного листа задайте `IMX519_WIDTH=1920 IMX519_HEIGHT=1440`.
Новые пакеты и системный сервис не нужны. После `sync-to-radxa.sh` запустите
на Q6A (можно через обычный SSH-сеанс):

```sh
cd ~/camera-imx519
python3 web-preview.py --host <адрес-Q6A-в-LAN>
```

Скрипт выбирает `runtime/preview`, если ссылка существует, и оставляет
`runtime/current` без изменений. На проверенной Q6A `runtime/preview`
указывает на сохранённую сборку `imx519.af1`: она даёт цветной поток со
штатным CAMSS после перезагрузки. Текущая сборка `imx519.pdaf5` требует
экспериментального CAMSS для фазового потока и не подходит для предпросмотра
со штатным модулем. Выбор можно переопределить переменной `IMX519_RUNTIME`.

Откройте `http://<адрес-Q6A-в-LAN>:8765/` на Mac. Совместите центр миры с
перекрестием и убедитесь, что все четыре края листа видны. Сервер доступен
в локальной сети без авторизации, поэтому используйте доверенную сеть.
`Ctrl-C` завершает
предпросмотр. Пока он работает, `qcam`, `snapshot.sh` и другие захваты этой
камеры запускать нельзя. Для другого кода линзы укажите
`python3 web-preview.py --focus 2432`; ключи `--width`, `--height` и `--frames`
меняют размер и частоту обновления. Это инструмент кадрирования; задержка и
повторный запуск камеры не подходят для измерения скорости автофокуса.
В пробе с мирой на расстоянии около 22 см контрастный AF выбрал код 2305; для этой
сцены можно запустить `python3 web-preview.py --host <адрес-Q6A-в-LAN> --focus 2305`.
Если предпросмотр запущен как временная служба `imx519-web-preview.service`,
завершите его командой `systemctl --user stop imx519-web-preview.service`.

## Повторная установка с исходников

На рабочем компьютере из каталога этого проекта:

```sh
export IMX519_SSH_TARGET='radxa@<board-address>'
bash target/sbc/radxa_dragon_q6a/sync-to-radxa.sh
ssh "$IMX519_SSH_TARGET"
```

Скрипт передаёт исходники, документацию и выбранные доказательства из docs.
Он не переносит build/artifacts и бинарные модули, не удаляет результаты
на плате и не меняет загрузку.
Удалённый rsync не нужен. На **плате с указанным выше ядром**:

```sh
sudo apt-get update
sudo apt-get install -y build-essential linux-headers-$(uname -r) device-tree-compiler dkms
cd ~/camera-imx519
bash build.sh
sudo bash install.sh
sudo reboot
```

После загрузки выполните `check.sh`, `capture.sh raw`, `capture.sh rgb` и
сохраните снимок `collect-diagnostics.sh`. Сборка сверяет хеши исходников,
компилирует модули, проверяет vermagic и наложение overlay на штатный DTB.
Само ядро целиком не пересобирается.

Установщик проверяет модель, ядро и конфликты CAM3, устанавливает
libcamera/V4L2-инструменты и DKMS-модули. Перед включением overlay сохраняет
конфигурацию в `/var/backups/imx519-cam3.*`. Использует каталоги и функции
установленного rsetup для EFI и присутствующей конфигурации U-Boot.
Автоматической перезагрузки нет. Повторно запускать установщик только ради
захвата кадров не требуется.

Системные изменения требуют пароля sudo, которого нет в неинтерактивном
SSH-сеансе агента. Пароль вводится в терминале платы.

## Подключение и overlay

Распиновка модуля: [справочник IMX519](../../../docs/reference/pinout.md).
Q6A J7/CAM3 имеет 15 контактов с шагом 1 мм и две линии CSI;
питание разъёма 3,3 В, I2C/reset проходят через преобразователи 1,8↔3,3 В.
Разводка J14/CAM1 отличается и требует отдельного подключения.
Подготовка ОС, boot firmware и общие интерфейсы описаны в
[репозитории платы Q6A](https://github.com/pOmelchenko/radxa_dragon_q6a).

CAM3 подтверждён пользователем. Привязка: CCI1/I2C1, сенсор `0x1a`, линза
`0x0c`, CSIPHY3, GPIO78 включения модуля; clock 24 MHz, link frequency
408 MHz из используемого драйвера. Пакет резервирует 256 MiB CMA.
Штатные overlay IMX219/IMX708 для CAM3 должны оставаться выключенными.

Номера I2C-шины, media и subdev могут меняться. В проверенном запуске:
`20-001a`, `20-000c`, `/dev/media0`, `/dev/v4l-subdev27`, `/dev/v4l-subdev28`.
`/dev/video0` и `/dev/video1` принадлежат Iris codec.

## Отключение и обновления

В `sudo rsetup` → Overlays → Manage overlays снимите отметку
`Enable Arducam IMX519 on CAM3 (experimental)`, сохраните и перезагрузитесь.
Это отключает камеру; исходники и DKMS-пакет остаются для повторного включения.
Процедура отключения описана по rsetup, на работающей камере не проверялась.

При проблеме загрузки можно выбрать оставшееся ядро `6.18.2-3-qcom` в EFI-меню;
его EFI overlay установщик не меняет. Этот способ восстановления не проверялся.
Старая конфигурация U-Boot может ссылаться на общий `/boot/dtbo`, поэтому
старое ядро в U-Boot не следует считать гарантированным откатом overlay.

После обновления ядра DKMS попробует пересобрать модули. Новый ABI и перенос
пользовательского overlay в EFI-каталог нового ядра нужно проверить отдельно.
Установщик намеренно ограничен уже проверенным `7.0.11-6-qcom`.

Контрастный AF и опытный PDAF добавлены 2026-09-25. Фазовый путь проверен
на одной неподвижной сцене; длительная работа и автоматическая перенаводка
между дистанциями ещё не квалифицированы.
Максимальное разрешение, другие частоты кадров,
цветовая/оптическая калибровка и поведение на новом ядре остаются отдельными проверками.
Системные libcamera-пакеты и параметры загрузки в этом продолжении не менялись.

Для повторного теста пропускной способности без записи всех кадров
(этот тест не проверяет резкость):

```sh
IMX519_RUNTIME="$PWD/runtime/preview" bash stability.sh rgb 9000
```

Профиль `libcamera/tuning/simple/imx519.yaml` используется первым.
В runtime также сохранён первоначальный базовый профиль из сборки.
Чтобы сравнить с ним: `IMX519_TUNING_DIR="$PWD/runtime/current/share/libcamera/ipa" bash snapshot.sh`.
Целевая MSV яркость изменена с 2.5 на 2.0; gamma 2.2, AWB speed 0.2.
Путь фактически выбранного YAML записывается в capture.log.
