# IMX519 на Radxa Dragon Q6A

**Статус: разработка; рабочий захват и автофокус не подтверждены.**
Рассматривается имеющийся 80° autofocus-модуль. Физическую ревизию, разъём
и комплект кабеля нужно зафиксировать до выбора порта.

## Подключение

Для показанного UC-875 Rev.B исходные материалы дают 15 контактов и
двухлинейный CSI. Q6A J16/CAM2 и J7/CAM3 имеют 15 контактов с шагом 1 мм,
две линии и [распиновку Raspberry Pi](https://docs.radxa.com/en/dragon/q6a/hardware-use/mipi-csi).
Это кандидат для подключения после сверки
[назначений камеры](../../../docs/reference/pinout.md), питания,
управляющих сигналов и контактной стороны обоих концов шлейфа.

I2C/reset J16/J7 проходят через преобразователи 1,8↔3,3 В,
питание разъёма 3,3 В. Цепи XCLK имеют необязательные резисторы — важно,
что установлено на конкретной плате. J14/CAM1 — другой интерфейс:
31 контакт, 0,3 мм, четыре линии и управляющая шина 1,8 В;
пассивный кабель не определяет согласование управления.
Схема V1.21: PDF стр. 32, лист 34/37;
[справочник Q6A](https://github.com/pOmelchenko/radxa_dragon_q6a/blob/main/docs/reference/hardware.md#камерные-разъёмы).

Если физический IMX519 имеет 22 контакта, нужно определить его вариант
и подтверждённую распиновку. Противоречивые `Top/Bottom` в каталоге Arducam
не определяют ориентацию имеющегося разъёма.

## Порядок разработки

1. Зафиксировать обе PCB, порт и проверенную схему кабеля. Проверить
   3,3 В, I2C, управляющие сигналы, тактирование и порядок питания.
2. Подготовить ОС по [репозиторию Q6A](https://github.com/pOmelchenko/radxa_dragon_q6a)
   и закрепить установленный BSP: ядро, DT и исходники.
3. Определить сенсорный драйвер IMX519 и драйвер привода объектива для
   этого BSP. Привязать I2C, clock/reset/supplies и CSI endpoints к Q6A.
   Pi overlay и установка пакетов Arducam для Pi не задают CAMSS-маршрут.
4. Согласовать двухлинейный CSI и RAW-формат по media graph, получить один
   кадр и проверить Bayer, crop, экспозицию/gain. Выбрать пригодный
   userspace/ISP; подтвердить его совместимость с драйвером.
5. Проверить ручное управление приводом, затем алгоритм автофокуса
   и его метаданные. Зафиксировать фокус для калибровки объектива.
6. Измерить длительный поток, пропуски и ошибки CSI; определить смысл
   временных меток для rolling shutter. Перенос advertised Jetson fps
   на Q6A не является подтверждением режима.

В [перечне Radxa](https://docs.radxa.com/en/dragon/q6a/hardware-use/mipi-csi)
IMX519 не названа среди совместимых камер. Нужная комбинация BSP, драйвера
и userspace в пакете не квалифицирована.

## Диагностика подготовленного Linux

После установки `v4l-utils` на целевую Q6A:

```sh
uname -r
cat /etc/os-release
v4l2-ctl --list-devices
media-ctl -d /dev/media0 -p
```

Выбрать реальный CAMSS media device вместо примерного `/dev/media0`.
Проверить entities, links и форматы pads. Наличие драйвера в исходниках
или sensor entity не доказывает захват и автофокус; готовой команды
STREAMON для этой связки пока нет.
[Контракт V4L2](https://www.kernel.org/doc/html/latest/userspace-api/media/v4l/dev-subdev.html).

Этот каталог содержит работу по данной связке. `vendor/`, `build/`,
`runs/` и Python caches — локальные файлы, исключённые из Git.
Результаты оформляются по [критериям](../../../docs/development/README.md).
