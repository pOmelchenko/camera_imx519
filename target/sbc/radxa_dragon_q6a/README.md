# IMX519 на Radxa Dragon Q6A

На CAM3/J7 проверен повторный захват RAW10 с имеющимся 80° модулем IMX519
при I²C 100 кГц. На плате использовалась отдельная тестовая запись EFI.
Ревизия камеры и артикул шлейфа неизвестны.
[Протоколы захвата и условия испытаний](../../../docs/guides/sbc/radxa_dragon_q6a.md).

## Подключение

Для показанного UC-875 Rev.B исходные материалы дают 15 контактов и
двухлинейный CSI. Q6A J16/CAM2 и J7/CAM3 имеют 15 контактов с шагом 1 мм,
две линии и [распиновку Raspberry Pi](https://docs.radxa.com/en/dragon/q6a/hardware-use/mipi-csi).
Это кандидат для подключения после сверки
[назначений камеры](../../../docs/reference/pinout.md), питания,
управляющих сигналов и контактной стороны обоих концов шлейфа.

I2C/reset J16/J7 проходят через преобразователи 1,8↔3,3 В,
питание разъёма 3,3 В. Цепи XCLK имеют необязательные резисторы — важно,
что установлено на конкретной плате. J14/CAM1 — другой интерфейс:
31 контакт, 0,3 мм, четыре линии и управляющая шина 1,8 В;
пассивный кабель не определяет согласование управления.
Схема V1.21: PDF стр. 32, лист 34/37;
[справочник Q6A](https://github.com/pOmelchenko/radxa_dragon_q6a/blob/main/docs/reference/hardware.md#камерные-разъёмы).

Если физический IMX519 имеет 22 контакта, нужно определить его вариант
и подтверждённую распиновку. Противоречивые `Top/Bottom` в каталоге Arducam
не определяют ориентацию имеющегося разъёма.

## Порты и профиль модуля

| Разъём | Шина сенсора и объектива | Приёмник | GPIO включения |
| --- | --- | --- | --- |
| CAM1 / J14 | `cci0_i2c0` | CSIPHY0 | 36 |
| CAM2 / J16 | `cci1_i2c0` | CSIPHY2 | 77 |
| CAM3 / J7 | `cci1_i2c1` | CSIPHY3 | 78 |

По умолчанию выбран **CAM3/J7** для проверки рядом с IMX296 на CAM1 и AR0234 на CAM2.
На J14 нужен подходящий переходник с согласованием управляющих уровней.
Во всех трёх профилях используются две линии данных и link frequency 408 МГц.
Сенсор `sony,imx519` по адресу `0x1a` ссылается через `lens-focus` на
`asahi-kasei,ak7375` по адресу `0x0c` той же шины. Профиль предполагает
генератор 24 МГц и внутренние стабилизаторы модуля с общим сигналом разрешения.
Внешний XCLK с Q6A не подаётся. Соответствие генератора, питания и привода
физической ревизии камеры предстоит проверить.
[Контракт драйвера и оверлея Raspberry Pi](https://github.com/raspberrypi/linux/blob/42d9bb9081f1c55e11abb5cbf4d7bede01d7bdde/arch/arm/boot/dts/overlays/imx519.dtsi).

## Установка для аппаратной проверки

На Mac или Linux из корня этого репозитория выполните

```sh
sh target/sbc/radxa_dragon_q6a/deploy.sh radxa@radxa-dragon-q6a.local cam3
```

Скрипт доставляет комплект в `~/q6a-imx519` и запускает установку через SSH.
Для установки непосредственно на Q6A перейдите в этот каталог или в
`target/sbc/radxa_dragon_q6a` локального клона и выполните

```sh
sudo python3 install.py --port cam3
```

Нужны обычная установка Radxa OS с EFI в `/boot/efi`, запись загрузки для
работающего ядра и пакеты Radxa. Установщик проверяет итоговый DTB, соседние
маршруты и уже привязанные устройства I²C, SPI и DSI. На занятом порту он
показывает прежнюю камеру и запрашивает подтверждение. Enter отменяет замену.
Для заранее подтверждённой замены добавьте `--replace` к команде установки
или доставки. Если профиль также управляет посторонней периферией, установщик
остановится до изменения EFI.

На CAM3/J7 штатный профиль задаёт I²C 100 кГц и задержку включения 100 мс.
На стенде удалось 9 из 9 независимых запусков RAW10 при 100 кГц. При 400 кГц
две отдельные серии дали 0/3 и 2/3.
[Протокол измерений](validation/cam3-2026-11-22.json).

При новой установке и обновлении штатного комплекта используется
`imx519-cam3-100khz.dtbo`. Старые записи EFI могут по-прежнему ссылаться на
`imx519-cam3.dtbo` или `imx519-cam3-400khz.dtbo`. Для ранее установленного
пользовательского профиля под одним из этих имён установщик берёт его копию,
изменяет частоту шины и включает её в выбранную запись EFI. Имя копии включает
хеш источника. Установщик проверяет задержку регулятора, маршруты соседних камер
и наличие других устройств на общей шине перед публикацией файлов.

Для CAM3 модуль IMX519 собирается с [поправками к metadata pad и runtime PM](patches/imx519-linux-7.patch).
После перезагрузки проверьте `cat /sys/module/imx519/version` и
`modinfo -F version imx519`: ожидается `q6a-cam3.1` в обоих случаях.
Если заменён прежний файл `updates/imx519.ko`, его копия остаётся рядом
под именем `imx519.ko.before-q6a-cam3`. Для отката восстановите прежний файл
(или удалите созданный override, если раньше загружался модуль из дерева
ядра), выполните `sudo depmod -a` и перезагрузитесь с прежней записью EFI.
Один модуль обслуживает все экземпляры IMX519 в данном ядре.

Для недостающих `imx519` и
`ak7375` он устанавливает заголовки работающего ядра и инструменты сборки
при необходимости, проверяет SHA-256 исходников и запускает Kbuild.
[Ревизия исходников и контрольные суммы](drivers.py).
Для сборки без загрузки исходников положите `imx519.c` и `ak7375.c` из этой
ревизии в `vendor/` рядом с `install.py` до доставки. Для полностью автономной
установки на плате также должны быть зависимости из APT. После обновления
ядра запустите установщик для новой версии.

Если установщик сообщил об изменении загрузочной конфигурации, выполните
`sudo reboot`. Исходные файлы конфигурации сохраняются перед первым изменением
под именами `*.before-imx519`. Для отката верните прежнему DTBO в каталоге
`dtbo/` имя без `.disabled`, затем восстановите нужные записи EFI и
`loader.conf` из копий. Ссылки других загрузочных записей на прежний DTBO
переносятся на его копию в `imx519-saved-overlays/`. Список модулей камеры
находится в `/etc/modules-load.d/q6a-imx519.conf`.

## Первый кадр и проверка фокуса

После обычной загрузки на Q6A в каталоге комплекта выполните

```sh
cd ~/q6a-imx519
python3 capture.py --port cam3
python3 capture.py --port cam3 --size 4656x3496 --focus 500
```

Первый вызов запрашивает 1920×1080. Второй задаёт полный размер и ручную
позицию привода для этого кадра. Камера выбирается по связи с CSIPHY, а привод
по шине выбранного сенсора. Скрипт подбирает свободный маршрут CSID/VFE,
проверяет согласованные Bayer и размер, затем освобождает добавленные связи.
В отдельном каталоге `imx519-…` сохраняются упакованный RAW10 `frame.raw` с
шагом строки V4L2, сведения о формате `frame.json` и цветной `preview.ppm`
половинного разрешения. Поле `v4l2_controls` в JSON содержит целочисленные
`exposure` (строки), `analogue_gain` и `digital_gain` (коды драйвера),
прочитанные с выбранного сенсора после согласования формата перед запуском
потока. При ошибке чтения скрипт выводит предупреждение и записывает
`v4l2_controls: null`. В более ранних файлах поле отсутствует. Превью использует порядок Bayer сенсора и старшие
8 бит каждого отсчёта, без баланса белого и обработки ISP.

Чтобы проверить движение объектива, снимите одну неподвижную контрастную
мишень с разными значениями `--focus` и сравните резкость. Драйвер AK7375
принимает 0…4095. Это управление позицией. Автоматический выбор позиции
требует алгоритма автофокуса и отдельной проверки.

## Состояние проверки

Оба внешних модуля собраны для ARM64 с заголовками Radxa `7.0.11-7-qcom`.
На DTB того же релиза проверены 15 порядков наложения профилей, замена шести
штатных профилей камер, замена IMX296 и AR0234 на каждом порту и добавление
IMX519 на CAM3 в конфигурацию IMX296/CAM1 + AR0234/CAM2. Испытания выполнялись
на файловых копиях. [Пакеты ядра и заголовков Radxa](https://github.com/radxa-pkg/linux-qcom/releases/tag/7.0.11-7).

На Q6A с загруженным драйвером `q6a-cam3.1` физически проверены повторный
запуск CAM3 при 100 кГц и отклик RAW10 на изменение выдержки. Стенд использовал
отдельную запись EFI, собранную поверх действующей конфигурации. Длительный поток
при 100 кГц, работа камер одновременно и движение привода фокуса остаются
отдельными проверками. При отсутствии сенсора проверьте журнал ядра для
`imx519`, `ak7375`, `cci` и `camss`.
[Критерии аппаратной проверки](../../../docs/development/README.md).

## Повтор прогона CAM3 на установленном модуле

После перезагрузки проверьте `uname -r`, `cat /sys/module/imx519/version`
и `modinfo -F version imx519`. Для этой проверки загруженный и установленный
модули должны показывать `q6a-cam3.1`. Сначала выполните
`python3 ~/q6a-imx519/capture.py --port cam3` и сохраните каталог RAW10 с
`frame.json`. Для сравнения с октябрьским опытом используйте ту же версию
программы просмотра. Команды ниже собирают только пользовательскую программу
и запускаются в графической сессии платы, когда камера свободна. Требуются
`git`, `make`, C++17 и пакеты разработки libcamera, SDL2 и GLESv2.

```sh
(
  set -eu
  trial=$(mktemp -d "$HOME/imx519-cam3-trial.XXXXXXXX")
  echo "$trial"
  git -C "$trial" init -q
  git -C "$trial" fetch --depth=1 https://github.com/pOmelchenko/camera_imx519.git 93c6e57ca556b0f96ca250a1414a4347fc280b2b
  git -C "$trial" checkout -q --detach FETCH_HEAD
  cd "$trial/target/sbc/radxa_dragon_q6a"
  make demo
  sh tools/preview.sh --list-cameras
  sh tools/preview.sh --camera='/base/soc@0/cci@ac4b000/i2c-bus@1/imx519@1a' \
    --frames=600 --compare --snapshot="$trial/comparison.ppm" > "$trial/preview.log" 2>&1
  tail "$trial/preview.log"
  sha256sum "$trial/comparison.ppm"
)
```

Зафиксируйте версию ядра и libcamera, фактические форматы и stride, число
кадров, частоту по меткам времени, счётчики пропущенных при выводе кадров
и ошибок захвата. Проверьте журнал текущей загрузки на ошибки CCI/I²C.
Сопоставьте результат с исходным протоколом. Сохраните незавершённый прогон
с его журналом, если камера не зарегистрировалась или остановилась до 600 кадров.
